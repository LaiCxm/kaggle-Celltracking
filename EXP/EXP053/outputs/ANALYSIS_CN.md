# EXP053 设计审计

## 目的

EXP049 的 `cos060` 在四个完整验证视频上已经把一个真实分裂恢复为
可评分的 division，但仍有三个 FN。EXP045 的原始排名审计显示，剩余真实
分裂中至少有一条 rank-3 备用边的概率并不低；该边被保存在 EXP052 的
延迟候选账本中。本实验检查阻断来自哪一个结构门。

## 单变量定义

Top-3 候选捕获、第一边/备用边概率下限、父子距离、姐妹距离上限、余弦门、
DeepCenter、下一帧存在性、每帧上限和全局上限全部锁定。相对 Top-3 基线
只改变一个参数：

| 分支 | 姐妹距离下限 | 不对称上限 | 发散增益下限 |
|---|---:|---:|---:|
| 基线 | 8.0 | 0.60 | 2.25 |
| 姐妹距离 | 7.5 | 0.60 | 2.25 |
| 不对称 | 8.0 | 1.10 | 2.25 |
| 发散增益 | 8.0 | 0.60 | 1.75 |
| 联合诊断 | 7.5 | 1.10 | 1.75 |

联合分支用于观察门之间是否存在交互，不作为单变量收益解释。每个分支
都在同一份确定性预测图上运行官方 patched scorer，不能用候选数量或旧的
4-video proxy 代替正式分数。

## 已知针对性证据

审计到的 `6bba_07e24132` rank-3 真边约为：姐妹距离 7.9608 µm、距离
不对称 1.0509、后继发散增益 1.8986 µm。它同时跨过三个基线门，因此
单变量分支预计都不能单独恢复这条边；联合分支才可能覆盖它。这个事实
使本轮结果可以区分“某一门是主阻断”与“多个门叠加阻断”，也避免把单纯
增加 Top-3 误判为候选召回成功。

## 判定标准

记录总分、普通边 Jaccard、division TP/FP/FN、结构候选数、DeepCenter
拒绝数、发散拒绝数和最终新增/重连边数。只有 division TP 增加且普通边
没有明显退化的分支，才进入后续测试集提交候选；本 Notebook 不生成
`submission.csv`。

## version 1 工程失败记录

version 1 已完成全部七个官方评分分支并写出 CSV，随后在最终运行清单
单元残留旧变量 `EXP019_MODES`，触发 `NameError`，所以 Kaggle 将整次运行
标为 `ERROR`。这不是评分逻辑或数据挂载失败。version 2 已把清单变量和
实验标签统一为 `EXP053_MODES`，并重新推送；正式结果以 version 2 为准。

## version 2 正式结果

version 2 的七个分支均完成官方 patched scorer。结果如下：

| 分支 | 官方 CV | division TP/FP/FN | 相对 `exp049_cos060` |
|---|---:|---:|---:|
| `off` | 0.9406682102 | 1/0/4 | -0.0207993064 |
| `exp049_cos060` | 0.9614675166 | 2/0/3 | 基线 |
| `top3_baseline` | 0.9614675166 | 2/0/3 | 0 |
| `top3_asym110` | 0.9614675166 | 2/0/3 | 0 |
| `top3_diverge175` | 0.9614675166 | 2/0/3 | 0 |
| `top3_sister075` | 0.9614654033 | 2/0/3 | -0.0000021132 |
| `top3_joint` | 0.9614632901 | 2/0/3 | -0.0000042265 |

Top-3 延迟候选确实进入了候选账本，且放宽结构门会改变候选统计和少量最终节点/边；但没有任何分支把第三个 division 真阳性变成可评分的 fork。放宽姐妹距离和三门联合还造成了极小的普通边/节点退化，因此不能把候选数量增加解释为有效召回。

本轮没有证据表明姐妹距离、不对称度或下一帧发散增益中的任一单独门是主要阻断点。当前应暂停“继续放宽这三个门”的路线，保留 EXP049 `cos060` 作为生产候选；后续优先在 ILP 的 parent→两个 daughter 联合选择层定位为什么已有候选仍不能形成正确 fork，并在更多完整视频上复核 `cos060` 的泛化。
