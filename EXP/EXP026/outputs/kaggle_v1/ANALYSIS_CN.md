# EXP026 V1 最新评测分析

## 先说结论

没有发生模型能力缩减。EXP026 没有重新训练模型，也没有更换模型权重；Pilkwang 和 FOCUS3D 的推理流程、视频、事件样本与 EXP025 相同。本轮评测的是几何候选门，不是模型检测精度，也不是官方排行榜分数。

所谓“能力大幅缩减”来自把 `14µm/14µm` 的候选三元组召回误读成模型召回：

- 模型端点检测：`18/18` 个事件的父节点和两个 daughter 都被联合节点池匹配；
- `14µm/14µm` 候选门：只有 `14/18` 个完整三元组进入候选，召回 `77.8%`；
- 放宽到预注册选择的 `16µm` 父子门、`20µm` 双子间距门：完整三元组恢复到 `18/18`，召回 `100%`。

因此缩减发生在“候选生成门”，不是冻结模型本体。

## 与 EXP025 的直接对照

| 项目 | EXP025 固定门 | EXP026 最终开发门 |
|---|---:|---:|
| 父子距离门 | 14µm | 16µm |
| 双子间距门 | 14µm | 20µm |
| 事件数 | 18 | 18 |
| 父/双子端点全部匹配的事件 | 18/18 | 18/18 |
| 正确三元组进入候选池 | 14/18 | 18/18 |
| 候选总数 | 506 | 1,708 |
| FOCUS-only 候选数 | 250 | 776 |
| 相对 14/14 候选量 | 1.00x | 3.38x |
| 每事件平均候选数 | 28.1 | 94.9 |

对角线门限还显示：

- `16/16µm`：`17/18`，候选 `1,171`；
- `18/18µm`：`17/18`，候选 `2,214`；
- `20/20µm`：`18/18`，候选 `3,884`，是 `14/14` 的 `7.68x`；
- 非对称的 `16/20µm` 已经完整召回，但只需 `1,708` 个候选，因此被预注册规则选中。

## 为什么看起来像“模型变弱”

EXP025 的 `14/14µm` 门把“端点已检测到但距离稍大”的真实 division 三元组提前删掉了。EXP026 的逐事件距离表显示，新增召回来自这些边界事件：

- `44b6_eb2880fc:282`：父子所需 `14.80µm`、双子 `12.69µm`；
- `6bba_87289e13:563`：父子 `10.66µm`、双子 `14.26µm`；
- `6bba_c328f2fd:65`：父子 `13.10µm`、双子 `14.63µm`；
- `6bba_c328f2fd:260`：父子 `14.17µm`、双子 `18.24µm`。

这些事件不是没有被模型看到，而是被 `14µm` 的候选规则裁掉。

## FOCUS3D 是否造成缩减

也不是。EXP026 的联合池仍保留 Pilkwang、共识和 FOCUS-only 三类节点。放宽门后候选量增加，其中包含 FOCUS-only 的候选从 250 增至 776，但这代表候选噪声和计算负担增加，不代表检测器失去能力。

本轮没有给 FOCUS3D 轮廓额外权重，也没有运行全局选择器，所以不能从 EXP026 判断最终图分数会升还是降。

## 推理耗时核对

本轮 Pilkwang 选定帧约 `411.2 秒`，FOCUS3D 约 `530.7 秒`。与 EXP025 的约 `422.8/527.8 秒` 同量级，没有出现模型退化或输出缩减导致的异常提前结束。

## 当前可用结论

1. 冻结模型端点召回在这 18 个事件上是 `18/18`；
2. `14/14µm` 候选门的三元组召回只有 `14/18`，是当前瓶颈；
3. 开发阶段可使用 `16/20µm` 作为全局选择器候选门输入；
4. 该门限来自同一开发事件面板，尚不是泛化 CV 最优，也没有官方 LB 证据；
5. 放宽后候选数增加 `3.38x`，下一步必须依靠全局约束和来源激活代价抑制误选，不能直接把 1,708 个三元组全部写入图。
