## 一、近期公开 Notebook

### Aman Atar — Geometric Fusion【中高，待独立复跑】

- 来源: https://www.kaggle.com/code/amanatar/biohub-geometric-fusion
- 2026-09-21 更新，票数约 166，使用 Pilkwang DeepCenter、seed314159 和 support-pack，T4、断网。
- 配置仍以 frozen dual-seed/harmonic pipeline 为主：detector threshold=0.965、bidirectional edge weight=0.15、DeepCenter TTA、gap2、safe-division 和 `tight55`/后处理扫描；新增的是验证器门控的 extended post-process sweep 与 weak-leaf pruning 选项。
- 可借鉴程度: 中高。它说明收益仍主要来自推理配置和结构后处理，不提供可直接归因于单一模块的干净消融。先做固定官方 scorer 复跑，不把标题或 proxy 当作 LB。

### Evgen Dvorkin — 0.947 LB / proxy 0.9490【中，需核对 provenance】

- 来源: https://www.kaggle.com/code/evgendvorkin/biohub-0-947-lb-proxy-score-0-9490
- 2026-09-20 运行，票数约 134；公开标题同时写 `0.947 LB` 和 `PROXY_SCORE=0.9490`，二者不能互相替代。
- 源码延续同一 frozen pipeline 和 DeepCenter TTA，使用 `MOTION_RELINK_TIGHT_UM=5.5`，并包含 neighbourhood-flow motion prior、discarded detection readmit、sub-threshold peak gap fill 等候选模块；这些模块是否真正被选中需以运行日志和 submission provenance 核验。
- 可借鉴程度: 中。若复用，必须先固定 `tight55`，再逐个做 flow/readmit/gap-fill 消融，禁止把多个开关一起移植。

## 二、近期 Discussion 信号

### “magic or overfitting?”【高，诊断价值】

- 来源: https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/740145
- 讨论显示 improved cell detection 主要用于生成更密集、更准确的训练样本，而不是直接替换推理检测；作者报告 refine probability、峰值删除和定位误差改善，但没有给出本项目可复现的官方 CV/LB。
- 可借鉴点: 检测器改进应先验证端点召回和定位误差，再判断 edge recall；不能只看后处理后的边分数。

### HOCT/FOCUS3D 后续讨论【中高，未形成生产证据】

- 来源: https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/738217
- 近期回复提到 FOCUS3D 分割经 Ultrack 生成稠密轨迹后，直接 edge Jaccard 约 0.7；也有人报告用稠密 FOCUS3D 标签训练 detector/linker，在未见样本上达到约 0.90 edge Jaccard，但这些是作者自报验证结果，不是 patched scorer 复跑。
- 另一条实用建议是先用 FOCUS3D 预训练，再学习从 FOCUS3D 中心到 Kaggle 稀疏中心的坐标偏移；这属于重新训练/域校准方向，不能混入当前 frozen-weight 后处理实验。
- 结论: 继续把 FOCUS3D 作为后置换边证据的收益证据不足；若重启，应从训练数据和节点坐标校准层开始设计。

### 端到端长窗关联讨论【中】

- 同一讨论串提出用 5–10 帧轨迹假设统一选择，而不是逐帧或逐边局部排序；同时指出单纯 link probability、没有 ILP/间隙填充的基线约 0.90 edge Jaccard。
- 可借鉴程度: 中。它直接针对“局部边选择无法恢复全局轨迹”的瓶颈，但需要新的训练/验证协议，当前不应在 EXP054 结果前叠加。
