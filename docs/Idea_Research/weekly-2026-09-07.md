### FOCUS-3D / HOCT 稠密检测与长窗关联【中高】

- 来源：https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/738217
- 要点：作者建议用 FOCUS-3D 或其他稠密实例分割生成外部 cell centroid，再用 Kaggle 稀疏标注做坐标偏差校准（`Kaggle zyx = FOCUS3D + dzyx`）；随后训练 link/track transformer，窗口可从相邻 2 帧扩到 5–8 帧。讨论中一个无 division 样本报告 node recall `1.0`、edge recall `0.9644`，但不是官方 LB。
- 可借鉴程度：**中高**，可能直接改善当前 division candidate recall=0，但工程和泛化风险高。
- 建议实验：新建训练型大实验；先测外部 detector 对 Kaggle 节点的 hit-rate、坐标误差和 estimated node count，再决定是否训练长窗 transformer。不得直接替换生产基线。

#### 738217 原帖逐条核对（2026-09-10）

- 主题：`focus3d : one of the best 3d cell segmentation`，作者 `hengck23`；Kaggle CLI 返回 35 条评论、30 票。原帖的主线不是“把 FOCUS3D 直接接到现有提交”，而是“用它生成稠密训练信号，再训练适配 Kaggle 稀疏坐标的检测器和关联器”。
- `3520759`：作者明确建议先测 FOCUS3D 对 Kaggle 稀疏节点的命中率和距离误差；满意后用 FOCUS3D 质心训练 link/track transformer，最后再用简单 U-Net 蒸馏成点预测器。目标是接近 100% 节点召回，同时减少冗余节点。
- `3520950`：公开 `cell-point-detector` 是用 FOCUS3D 稠密质心加 Kaggle 标注训练 3D U-Net 点检测器，单 T4 约 6 秒/volume；后续路线是 detector → detector feature/link transformer → 5 帧以上长窗口关联，减少 gap heuristic 依赖。该 Notebook 不是原始 FOCUS3D 实例分割模型。
- `3521418`：推荐用两个 head 做域校准：一个预测 FOCUS3D 坐标，另一个预测 Kaggle 坐标相对 FOCUS3D 的 `dzyx` 偏移；最终 `Kaggle zyx = FOCUS3D zyx + dzyx`，偏移直接用物理单位预测，而不是量化网格坐标。
- `3521474`：在排除 division 的未见样本 `6bba_337b1b3a` 上，作者报告节点召回 `1.0`、端到端边召回 `0.964433`。这是检测/普通关联证据，不是 division 召回或官方 leaderboard 证据。
- `3522918`、`3522929`（最新）：作者和其他参与者都表示 Ultrack 的过分割处理没有解决；`ultrack-td` 配合 FOCUS3D 轮廓可以生成稠密轨迹，但截至该回复没有明确收益。因此 FOCUS3D + Ultrack 仍是研究方向，不是可直接替换 EXP010 的生产链。
- 接入判断：最稳妥的是把公开蒸馏点检测器作为额外候选节点源，或只在 gap/division 局部窗口查询原始实例 mask；必须保留 EXP010 的 Pilkwang detector、learned edge、ILP 和 safe-div 作为主干，并用官方 scorer 检查新增节点是否破坏普通 edge。禁止直接把 FOCUS3D 全量节点或物理 PP 替换整条 0.942 链路。

### Division 候选图覆盖率证据【高】

- 来源：https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/739516
- 要点：讨论中的训练集审计显示，简单 nearest-parent 候选图（半径约 `9.9 um`、每个节点最多 `10` 个候选）对 `151` 个 GT division fork 的覆盖约为 `88%`，而普通 continuation edge 的覆盖约为 `99.7%`。这不是最终 metric，但它证明 division 的误差会在分类器之前集中出现，并给 division Jaccard 设置候选召回上限。
- 评测提醒：通过“关闭 division 后的 LB 差值”反推 division Jaccard 并不严格，因为 parent-to-daughter edge 同时参与 edge Jaccard；必须调用官方 `evaluate_datasets()` 分别读取 edge/division 指标。
- 可借鉴程度：**高**，与 `EXP010` 的逐阶段审计一致：4 个 FN 中有 3 个先被错误 continuation 占用 daughter，另 1 个被 safe-div 几何门拒绝。
- 建议实验：先建立 recall-first triple evaluator，分别报告 GT parent、两个 daughter 及完整 `(parent, daughter1, daughter2)` triple recall；候选必须从 detector 输出直接枚举，不能只从 ILP 已选边中生成。

### FOCUS-3D 稠密伪标签与公开 detector checkpoint【高（检测候选）】

- 来源：
  - https://www.kaggle.com/competitions/biohub-cell-tracking-during-development/discussion/738217
  - https://www.kaggle.com/code/hengck23/cell-point-detector
  - https://www.kaggle.com/datasets/hengck23/hengck23-cell-point-detector-demo
- 要点：作者先用 FOCUS-3D 生成 dense instance centroids，再结合 Kaggle sparse annotations 训练/校准点检测器；建议双 head 形式 `Kaggle zyx = FOCUS3D zyx + dzyx`，其中偏移 head 用物理单位预测。公开 Kaggle Dataset 只有 `00000030.pth`（约 69.5 MB）和 `model_v5.py`，因此它是蒸馏后的 detector checkpoint，不是包含 lineage/division 真值的稠密标签集。
- 公开诊断：在 `6bba_337b1b3a` 上报告 sparse GT node `1272/1272` 命中，node recall=`1.0`，mean distance=`1.4339 um`，max distance=`5.1707 um`；预测 node `31932`，estimated node `30480`，ratio=`1.0476`，约 `5.1-6 sec/volume`（单 T4）。这些数字只证明节点检测潜力，不证明 division。

- 可借鉴程度：**高（用于扩充候选节点）**；最有价值的用法是与 Pilkwang/EXP010 detections 取 union 后测 GT triple recall，而不是立即替换整条推理链。

### Division Pair Verifier V1【高（可复用候选分类基线）】

- 来源：https://www.kaggle.com/datasets/qualzz/biohub-division-pair-verifier-v1
- 内容：约 5.51 MB，共 13 个文件；包含 parent+两个 daughter 的 verifier 权重、parent gate、geometry prefilter、后处理代码和训练摘要。README 明确说明仅用 Biohub competition training split 训练，不含 test prediction 或原始 volume。
- 数据规模：训练 manifest `14271` 个 plausible pairs，其中 `151` 个正例；sequence-held-out 验证 `2454` 个候选、`31` 个正例。
- 候选级结果：AP=`0.5929`、ROC-AUC=`0.9782`；最佳阈值约 `0.99234` 时 TP/FP/FN=`17/10/14`，候选级 Jaccard=`0.4146`，recall=`0.5484`。按预期事件数取 top candidates 时 `16/24` 为 TP，precision=`0.6667`。
- 限制：这些是“自然 plausible-pair 分布”的候选分类指标，不是把 fork 写回完整追踪图后的 official patched division Jaccard；也没有证明不会破坏 continuation edge。不能像 `EXP006` 一样直接让 verifier 改写普通图结构。
- 可借鉴程度：**高**，它至少证明公开的 recall-first pair 枚举能产生真实正例，且可作为我们 candidate evaluator 的外部 sanity check；是否接入 `EXP010` 必须先做完整 triple recall 和官方图级 scorer。

## 五、对项目的行动结论

1. 以 `EXP010-child000 / LB 0.942` 作为当前生产方案，保留 `EXP003-child000 / LB 0.926` 作为可回退 control；正式比较只使用 Kaggle 官方 LB，4-video proxy 仅用于故障诊断。
2. 下一优先级是 SDW `0.475 -> 0.30` 的单旋钮实验；必须新建 child、固定 12 movie scorer、记录 provenance，不能直接改生产配置。
3. 公开 `.946` lineage 的两个可拆分候选是 `tight55` 和 secondary edge-feature TTA；应分别单独验证，不能一次合并后把提升归因于某个模块。
4. Adaptive grouped confidence dominance 值得作为独立推理实验移植；禁止其改变 division parent 来源，并保留 motion-only control。
5. 当前 division verifier 路线继续冻结；先修真实 division candidate recall，再考虑分类器。下一步应比较三种节点源的完整 GT triple recall：Pilkwang/EXP010 detections、FOCUS-3D distilled detections、二者 union。
6. FOCUS-3D checkpoint 可先作为候选检测器，不应被描述为 division 数据集；FOCUS-3D/HOCT 的训练结果也不能外推到 division，除非验证集包含真实 fork 并通过官方 patched scorer。
7. `Division Pair Verifier V1` 是当前最值得先复用的 division 专项基线：先复刻其 plausible-pair 枚举并测完整 triple recall，再把其分数作为只增 fork 的 proposal signal；禁止它删除或替换 continuation edge。
8. `Regular Division GT No-Jitter Artifact` 证明 exact sparse GT 可以训练出非零 TP，但其 official-like division Jaccard 只有 `0.0545`，仅作为采样/训练蓝图，不直接部署。
9. ZebraHub/Ultrack 是目前最像“稠密 lineage 数据集”的方向，但在确认 license、fork 字段和坐标映射前不启动训练；`r51-sparse-select`、Local CV Pack、M001 outputs、StableDet-HOCT code 均不能充当 division 真值。
